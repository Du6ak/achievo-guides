# Формат руководства v1

Файл — UTF-8 Markdown с YAML Front Matter между отдельными строками `---`.
Байтовый лимит входного файла и канонического экспорта — 32768. YAML не отображается читателю.

Обязательные поля: `schema_version: 1`, `id` (канонический UUID в нижнем регистре), `app_id` (1…2147483647),
`achievement_api_name` (1…256 символов), `language`, `title` (1…160, одна строка), `guide_type`, `spoilers` (boolean).
Дополнительные: `summary` (до 500), `author_name` (до 80, одна строка), `translation_of` (UUID либо null),
`related_achievements` (до 32 уникальных API-имён той же игры, кроме основного), `source_urls` (до 16 HTTP/HTTPS ссылок по 2048 символов),
`content` (необязательное структурированное содержимое, описано ниже).
Пустая инструкция запрещена. Строковые лимиты считаются в UTF-16 единицах Kotlin; байтовый лимит — UTF-8.

Типы хранятся как `quick`, `detailed`, `safe`, `combo`, `alternative`; UI показывает русские названия.
Язык — стандартный канонический код BCP 47 в поддерживаемом профиле:
2–3 буквы языка, необязательный Script, необязательный REGION (`ru`, `pt-BR`, `zh-Hans`, `es-419`).
Новый язык не требует миграции БД. Интерфейс предлагает ru/en/de/fr/es/pt-BR/zh-Hans/ja/ko.

## YAML и безопасный Markdown

Поддерживается ограниченный профиль YAML 1.2: скаляры, массивы строк и JSON flow-объект `content`. Строки экспортируются JSON-кавычками,
что является корректным YAML и сохраняет кавычки, двоеточия, переводы строк и Unicode.
При чтении также допустимы простые некавыченные строки, одинарные YAML-кавычки и списки с `  - `.
Теги, якоря, алиасы, произвольные YAML-объекты, дубли и неизвестные поля запрещены. Объект `content` разбирается
типизированным JSON-десериализатором без конструирования произвольных классов.
Числовые поля и boolean должны иметь свой YAML-тип; `"620"` не заменяет число 620.

Разрешены абзацы, переносы, заголовки, списки, `**жирный**`, `*курсив*`, `_курсив_`, `__жирный__`
и ссылки `[подпись](https://example.org)`. HTML, JS, iframe, внешние изображения, блоки кода и ссылки-сноски не поддерживаются.
Локальные иллюстрации разрешены исключительно через проверенный манифест вложений `content`.
URL обязан содержать HTTP/HTTPS scheme и host, не содержать учётных данных, пробелов, управляющих символов и обратных слешей.
Вложенные скобки URL в экспорте кодируются как `%28`/`%29`.
Экранированные символы и HTML entities отображаются как текст, никогда как HTML.

Редактор не принимает YAML от пользователя. Поля формы сериализуются отдельно от тела; Markdown-значимые символы
текста экранируются, `<`, `>` и `&` заменяются entities. Поле формы не может внедрить YAML-ключ или исполняемую разметку.

## Пути, несколько способов и переводы

```text
achievo-guides/guides/{appId}/{language}/{achievementKey}/{guideId}.md
achievementKey = lowercase hex SHA-256(UTF-8(original achievement_api_name))
```

Не нормализуйте регистр API-имени перед хэшированием. Ни заголовок, ни исходное API-имя не используются напрямую как путь.
Один каталог достижения может содержать несколько UUID на одном языке.
Валидатор сверяет путь с метаданными, уникальность UUID всего набора и существование API-имён
в `schema/steam-achievements.json` — локальном снимке подтверждённых схем Steam.

Перевод — отдельный UUID и файл, `translation_of` ссылается прямо на оригинал.
Оригинал обязан существовать в наборе, иметь тот же AppID/API-имя/тип и другой язык.
Цепочки, циклы и ссылки на себя запрещены. Альтернативный способ получает новый UUID без `translation_of`.

## Статический каталог

`CommunityGuideCatalogBuilder` сканирует только `guides/`; точный пустой `.gitkeep` корня допускается как маркер Git,
но не публикуется. Символические ссылки, неожиданные файлы и каталоги отклоняются. `examples/` не сканируется.
Полный набор проверяется до создания результата.

```text
public/v1/catalog.json             # schemaVersion, generatedAt, languages[], games[]
public/v1/games/{appId}.json        # schemaVersion, appId, guides[]
public/v1/guides/.../{guideId}.md   # канонические UTF-8 документы
```

Запись games общего каталога содержит AppID, languages, indexPath и SHA-256 индекса.
Каждая запись guides индекса содержит metadata без `content`, path, SHA-256 опубликованных байтов файла.
Текст, структура шагов и манифест иллюстраций загружаются только при открытии Markdown.
Порядок игр и путей стабилен. generatedAt по умолчанию Unix epoch; CLI принимает явный timestamp.
Одинаковые входные данные и timestamp дают одинаковые байты.
Лимиты v1: общий JSON до 4 МиБ/50000 игр, индекс игры до 8 МиБ/10000 записей. Они проверяются и сборщиком, и клиентом.

Сборка создаёт временный соседний каталог, затем заменяет `v1`; предыдущая версия восстанавливается при ошибке замены.
Проверка входов выполняется до замены, поэтому повреждённый вход не удаляет старую публикацию.
Это офлайн-сборщик артефактов: при замене каталога возможен краткий промежуток между переименованиями;
публикацию на Pages позже следует выполнять атомарным деплоем артефакта.

## Переносимые команды

Из Achievo: `./gradlew.bat communityGuideTools`. Самостоятельно внутри перенесённого `achievo-guides/`:
`./gradlew.bat guideTools`. Оба используют одни исходники формата и проверки.

```powershell
java -jar tools/guide-tools.jar validate .
java -jar tools/guide-tools.jar build . public --timestamp=2026-10-24T00:00:00Z
java -jar tools/guide-tools.jar validate-file exported.md schema/steam-achievements.json
```

`validate-file` проверяет отдельный экспорт по снимку схемы без проверки его расположения в дереве;
`validate` проверяет также пути, уникальность и связи всего набора. JSON Schema описывает метаданные;
общий Kotlin-валидатор дополнительно проверяет текст, размер, ссылки, API-имена и межфайловые связи.
Следующая несовместимая версия потребует нового schema_version и каталога public/v2, сохраняя чтение v1.

## Структурированные блоки и управляемые вложения

Обновлённый читатель принимает прежний v1 без `content` и его аддитивное расширение с `content`.
Прежние сборки приложения не знают нового ключа и отклонят расширенный файл; для него нужен обновлённый читатель.
Обычные старые файлы не переписываются и не получают отмечаемые шаги автоматически.

`content` содержит `steps[]`, `tips[]`, `warnings[]`, `related[]`, `attachments[]`.
Шаг имеет постоянный UUID `id`, `parts[]` и авторский boolean `checkable` (по умолчанию false).
Связь содержит `achievementApiName`, отображаемый `title` и такой же `block` с UUID.
Каждая часть имеет UUID и вид `TEXT` с буквальным `text` либо `IMAGE` с `attachmentId` (SHA-256 PNG).
Порядок частей задаёт положение текста относительно нескольких иллюстраций. Все UUID блоков и частей уникальны внутри документа.

В манифесте иллюстрации указаны `sha256`, `byteSize`, `width`, `height`.
Разрешён только проверяемый PNG: до 4 МиБ, до 8192 px на сторону и 24 млн пикселей.
Редактор принимает PNG/JPEG и изображения буфера, преобразует в PNG без исходных метаданных.
На гайд допускается до 24 вхождений изображений, суммарно до 20 МиБ различных вложений. Лимит Markdown остаётся 32 КиБ.
Читатель использует уменьшенные копии до 1280 px; экспорт сохраняет полный размер.

```text
guides/{appId}/{language}/{achievementKey}/{guideId}.md
guides/{appId}/{language}/{achievementKey}/assets/{guideId}/{sha256}.png
```

Из `.md` используются только ссылки вида `![Иллюстрация](assets/{guideId}/{sha256}.png)`.
Путь вычисляется из проверенных идентификаторов; пользовательский путь или URL не сохраняется.
Сборщик требует точного соответствия вложений манифесту, проверяет PNG, целостность чанков/CRC и хэши, отклоняет лишние/отсутствующие файлы,
символические ссылки и небезопасные пути. Копирует изображения вместе с каноническим Markdown.
`validate-file` также проверяет соседнюю папку `assets`.

Для `content` тело Markdown обязано точно соответствовать общей функции генерации. Изображения и отметки нельзя
незаметно внедрить только в тело. Отмечаемый блок экспортируется как `- [ ] Шаг …`, его части остаются внутри пункта.
Личная галочка читателя в Markdown не сериализуется: хранится отдельно по профилю, guide UUID и block UUID.

Отдельная локальная команда `check-title-set` проверяет полный переданный набор
гайдов v1, включая существующие проверки UUID, переводов и вложений, и отклоняет
повтор ключа AppID, API-имени основного достижения, языка и названия. Порядок
запуска и требования к локальной схеме описаны в `README.md`.
Используется общая нормализация Kotlin с NFKC; применение NFKC пока не является
утверждённой политикой спецификации. Это проверка снимка, а не защита слияния.
